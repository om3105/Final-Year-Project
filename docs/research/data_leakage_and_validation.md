# Leakage prevention and validation protocol

The unit of splitting is **participant ID**, before slice creation, augmentation, normalization fitting, feature selection, missing-value imputation, class balancing, or hyperparameter tuning. All scans and visits from one person remain in exactly one partition. Repeated scans are either reduced to a predeclared baseline visit or handled longitudinally within one partition. No patient identifier, file path, scan date that reveals cohort, site-specific label proxy, or post-outcome variable may enter the model.

1. Define the prediction time and label first. A cognitive score used to assign an AD/MCI/CN label may be **target leakage** if inserted as an input at the same or later visit. Audit each assessment's collection time and diagnostic role; remove target-defining variables from the primary model or create a clearly labeled sensitivity analysis. Same-admission coding leakage is documented in `[35]`; diagnostic-feature leakage is tested in `[33]`.
2. Deduplicate by participant, visit, scan identifier and pixel hash. Examine near-duplicate scans and corrected series. Keep all 2D slices or 3D patches from a volume together. This is needed even if a prior study reports a subject-level split `[1]`.
3. Fit image intensity statistics, tabular imputers, encoders, standardizers, feature selection, and calibration **only on training folds**. Validation may guide model selection; a locked test cohort is used once for final reporting.
4. Group-stratify participants for class balance, with site and acquisition-protocol summaries. If feasible, reserve a truly external study or temporal period; do not report same-cohort cross-validation as external validation. OmniBrain's external ADNI result `[2]` illustrates why this matters.
5. Record an immutable split manifest with de-identified salted participant hashes, label definition, date cutoff, cohort version, and seed in a private research environment. Commit only aggregate counts and a manifest schema, never participant records.
6. Audit every derived feature's origin. MRI-derived radiomics, volume reports, and MRI-generated text are imaging derivatives, not independent clinical observations `[1]`. If they use post-label segmentation or annotations, assess leakage independently.
7. Report patient-level macro and per-class AUROC, AUPRC, F1, sensitivity, specificity, calibration, and confidence intervals. Resampling is by participant. Missing-modality tests must use the same held-out participants.

## Dataset-specific leakage checks

- **ADNI label meaning:** current `DXSUM.DIAGNOSIS` codes are CU, MCI and **dementia**, not CU/MCI/AD by default. AD etiology requires separate diagnostic fields. The project must not leak `DIAGNOSIS`, `DXAPP`, `DXAPROB`, `DXAPOSS` or clinician confidence into the predictors. [ADNI diagnostic guide](https://adni.loni.usc.edu/quick-start-guide-asset101625/diagnostic.html).
- **Diagnostic assessment circularity:** ADNI says CDR, MMSE and Logical Memory II contribute to cohort diagnosis. Same-visit scores are excluded from the primary independent-clinical feature set pending explicit review; if explored, report them as a target-proxy sensitivity analysis. [ADNI cohort criteria](https://adni.loni.usc.edu/quick-start-guide-asset/cohorts.html).
- **Visit linkage:** use actual MRI and clinical dates or OASIS-3 relative days, not a shared visit string alone. ADNI codes can span phases and several examination dates; NACC does not automatically assign MRI to a UDS visit. [ADNI table anatomy](https://adni.loni.usc.edu/quick-start-guide-asset/anatomy2.html), [OASIS FAQ](https://sites.wustl.edu/oasisbrains/home/oasis-resources-and-faq/), [NACC guide](https://www.naccdata.org/the-nacc-researchers-guide).
- **Cross-release overlap:** the OASIS team advises against treating OASIS-1, -2 and -3 as independent pooled cohorts. If any historical OASIS images are used, resolve overlap before splitting or external-test claims. [OASIS FAQ](https://sites.wustl.edu/oasisbrains/home/oasis-resources-and-faq/).
- **Merged and image-derived fields:** audit every `ADNIMERGE` candidate field back to its source. MRI morphometry, segmentation and reports are image-derived, and diagnostic/visit fields can reveal the target. [ADNI data organization](https://adni.loni.usc.edu/quick-start-guide-asset/data_org.html), [MRI data](https://adni.loni.usc.edu/data-samples/adni-data/neuroimaging/mri/).

The [cohort protocol](../data/dataset_access_and_cohort_protocol.md) fixes a scan/visit window before outcome analysis and requires an aggregate inclusion flow. A preliminary release count is never a training count.

**Acceptance gate:** zero participant overlap, zero slice/visit overlap, no preprocessing fitted outside training folds, signed feature-time provenance, and a locked test evaluation script. If any check fails, invalidate the run and retrain.
