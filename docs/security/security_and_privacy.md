# Security and privacy plan

**Current data posture:** no participant-level data in Git, AI prompts, public demonstrations, logs, analytics, model cards, or third-party storage. ADNI's [DUA](https://adni.loni.usc.edu/wp-content/themes/adni_2023/documents/ADNI_Data_Use_Agreement.pdf) and OASIS's [2025 DUA](https://bpb-us-e2.wpmucdn.com/sites.wustl.edu/dist/6/4383/files/2025/07/Data-Use-Agreement_July2025.pdf) govern their respective records. De-identification alone does not grant redistribution or public-cloud permission. This document does not claim HIPAA, GDPR or clinical-device compliance.

- **Upload:** allow only predeclared MRI formats and small bounded sizes; inspect MIME plus file signature and decoded dimensions; reject archives and malformed DICOM/NIfTI; strip direct identifiers and never echo filenames. Prevent path traversal and decompression bombs. Scan decoding runs in a constrained worker with time and memory limits.
- **Clinical form:** collect only predeclared variables, no free-text names or patient IDs. Validate units/ranges and measurement time. Keep browser state ephemeral, exclude patient values from URLs and telemetry.
- **Transport/storage:** TLS for all deployed traffic. Default backend behavior is transient memory or short-lived private scratch storage deleted after response/timeout. No database/history until retention period, user access, deletion and lawful hosting are approved. Encrypt any approved persistent store at rest and restrict service accounts.
- **Logs:** request ID, error code, timing, model version and aggregate QC only; no image pixels, clinical values, paths, headers containing tokens, SHAP values tied to a patient, or raw traces. Limit log access and retention.
- **Authentication/authorization:** a public demonstration uses synthetic cases only. Real-data inference would need authenticated authorized users, role checks, audit trail and dataset-specific authorization; CORS is not authentication.
- **Model abuse:** rate/size limits, no arbitrary checkpoint or URL loading, dependency and model artifact hash verification, non-executable serialization format where feasible, and malformed-image testing.
- **Release:** review checkpoints for data memorization/reconstruction risk and DUA permissions before Hub upload; never publish participant-level examples. Security review must approve any future history feature.
